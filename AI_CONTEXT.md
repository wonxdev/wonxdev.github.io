# AI_CONTEXT

## Project

Production portfolio website for wonxdev.

Minimal.

Balatro-inspired.

Vanilla JavaScript.

Static website.

Documentation-first.

---

## Primary Goal

Build a portfolio that demonstrates software engineering ability.

Not just visual design.

Architecture matters as much as appearance.

---

## Tech Stack

- HTML
- CSS
- Vanilla JS
- Vite

No frameworks.

---

## Rules

Never rewrite existing architecture unless required.

Always read nearby files before editing.

Reuse components.

Never duplicate CSS.

Never hardcode repeated content.

Never create placeholder implementations.

Never leave TODO comments.

Never introduce unnecessary dependencies.

---

## Folder Responsibilities

components/

Reusable UI.

data/

Portfolio content.

scripts/

Behavior.

styles/

Presentation.

assets/

Static files.

---

## Before Writing Code

1. Understand surrounding files.
2. Preserve architecture.
3. Prefer extension over replacement.
4. Check naming consistency.

---

## After Writing Code

Remove dead code.

Verify imports.

Check console.

Check responsive layout.

Update documentation.

---

## Coding Style

Readable > clever.

Small functions.

Single responsibility.

Named exports.

Alphabetical imports.

Semantic HTML.

CSS variables only.

---

## UI Style

Minimal.

Dark.

Subtle personality.

Large spacing.

Soft corners.

Low-motion.

Balatro inspiration only.

Never imitate Balatro literally.

---

## Animations

Short.

Purposeful.

Accessible.

Respect prefers-reduced-motion.

---

## Performance Targets

Performance 95+

Accessibility 100

SEO 100

Best Practices 100

---

## Definition of Success

Someone unfamiliar with the project should understand the codebase within 30 minutes.

The website should require data changes—not architectural changes—to update content.
